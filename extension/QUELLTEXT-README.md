# AdSilence — building the submitted package

This archive is the complete source of the AdSilence Firefox add-on
(`adsilence@adsilence.net`). Running the one command below reproduces the
submitted `.zip` exactly.

## Build environment

| | |
|---|---|
| Operating system | Linux or macOS. Any distribution; nothing distribution-specific is used. Windows works under WSL — one npm script sets an environment variable inline, which `cmd.exe` does not support. |
| Node.js | **22 or newer** (declared in `extension/package.json`, `engines.node`). Built and verified with 25.9.0. Install from <https://nodejs.org/en/download> or via `nvm install 22`. |
| npm | **10 or newer**, ships with Node. Verified with 11.12.1. |
| Network | Not required. Everything the build reads is in this archive. |
| Disk | About 400 MB for `node_modules` and the build output. |

No compiler, no Python, no native modules.

## Build

```bash
cd extension
npm ci      # installs exactly the versions in package-lock.json
npm run amo
```

`npm run amo` performs every step:

1. `scripts/listen-bauen.mjs` — converts the filter lists in
   `listen/quellen/*.txt` into declarativeNetRequest rulesets and the
   accompanying cosmetic/scriptlet files.
2. `scripts/build.mjs --ziel=firefox` — bundles background and content scripts
   with esbuild, the option and popup pages with Vite, copies the assets and
   writes `manifest.json`. Output: `dist/firefox/`.
3. `scripts/zip.mjs --ziel=firefox` — packs it into
   `dist/adsilence-firefox-<version>.zip`.

The result is byte-identical to the submitted package. Verified on 14.09.2026
by unpacking this archive into an empty directory, running the commands above
and comparing the checksum over all files of `dist/firefox/`.

## What is source and what is generated

Everything under `extension/src/`, `extension/scripts/`, `extension/manifest/`,
`extension/i18n/`, `extension/icons/` and `frontend/i18n.ts` is hand-written
source. Nothing is transpiled, minified or obfuscated — `minify: false` is set
explicitly in both bundler configurations (`scripts/build.mjs`), so the
submitted package contains readable code.

These directories are **generated** by step 1 and are included on purpose:

```
extension/rules/        declarativeNetRequest rulesets
extension/kosmetik/     CSS selectors per list
extension/scriptlets/   per-site fixes, mapped host -> entry
extension/popup/        per-site popup rules
extension/prozedural/   procedural cosmetic rules
extension/listen/bericht.json
```

They are regenerated by `npm run amo` before the build, so you never have to
trust them — but they are shipped so that the comparison succeeds. The filter
lists change daily; if you downloaded them fresh (`npm run listen:holen`), you
would get *different* rulesets than the ones in the submitted package and the
comparison would fail for reasons that have nothing to do with this add-on.
`listen/quellen/*.txt` are therefore the exact copies the submitted build used.

Each source and its URL is listed in `extension/listen/quellen.json`. One entry,
`listen/tarnung.txt`, is written by us and has no URL: it covers first-party
tracking that no public list carries. Every rule in it is commented with the
date, the site it was measured on, and what it must not break.
